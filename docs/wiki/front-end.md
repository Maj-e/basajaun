# Using the data in the front end

The page is plain HTML + JavaScript with **MapLibre GL 4.7.1**, self-hosted in `web/vendor/` (BSD-3 license included); no framework, no build. It only reads static files.

The screen follows the validated mockup (`docs/mockup/`) and the demo script (`docs/demo-script.md`): full-screen dark map, timeline strip along the bottom, two readouts, legend on the map.

## Modules
| File | Role |
|---|---|
| `config.js` | area, data paths, NASA GIBS imagery URL, reference towns, trail length |
| `map.js` | the single map (own dark basemap from `data/static/land.geojson`, graticule, towns), the satellite layer, `null` + error message when WebGL is unavailable |
| `layers/loader.js` | manifest → data → map layers; temporal fading; `ring` features; `glow`; legend; popups; layer list |
| `timeline.js` | strip chart from `daily_summary.json` and the playback engine (owns `state.hour`) |
| `story.js` | peak (day with most fires), computed from the data: highlighted bar + *Peak day* button |
| `alerts.js` | alert panel: one row per fire (region, people within 5 km, risk), click → the fire's detail (isolated on the map); type filters; rings on the map |
| `readouts.js` | active fires (last 24 h), strongest fire, total |
| `app.js` | wiring, controls, presenter keys, `?demo=1` |

Presenter keys: `Space` play/pause, `P` peak day, `←`/`→` one hour, `R` restart. The shared link loops by itself; `?demo=1` opens paused (kept when switching episode). A tab on top of the timeline folds the chart.

Popups use human labels and units (`FIELDS` in `layers/loader.js`), scroll when long and pan the map so they stay clear of the header and the timeline.

**Satellite image of the day** (Layers panel): NASA GIBS VIIRS true color for the playback day, dimmed so the fires stay brightest. Needs internet; the land outline is the offline fallback.

## How the page loads data
1. `web/map.js` creates the single map, framed on `view` from `web/config.js`.
2. `web/app.js` calls `loadData()` (manifest + each active layer's file), builds the timeline, then adds the layers once the map style is ready.
3. `web/layers/loader.js` fetches the **manifest** (`CONFIG.manifest`) and, for every layer with `active: true`, adds a source + layer according to its `type`.
4. Styles come **from the data**: `["get", "color"]`, `["get", "radius"]`, `["get", "border"]`…
5. The legend and the popups are generated from the manifest (`legend`, `popup` fields).
6. The status badge shows "Sample data" / "Live data", or "Layer unavailable: …" if a layer file fails.

The page reads **`web/data/manifest.json`** (generated by `make manifest`) and `web/data/processed/daily_summary.json`: the real FIRMS episode. Point `CONFIG.manifest` back to `data/sample/manifest.json` to work on sample data. It will switch to `web/data/manifest.json` when the real export exists (W1-F2).

## Layer types the loader knows
| `type` | MapLibre rendering | Style properties read from features |
|---|---|---|
| `circle` | points; `ring: true` features drawn as rings; manifest `glow: true` adds a halo | `color`, `radius`, `border`, `opacity`, `ring` |
| `fill` | polygons + outline | `color`, `opacity` |
| `line` | lines | `color`, `width` |
| `image` | georeferenced image (needs `corners` in the manifest) | — |
| `arrows` | *(planned, W3-F1)* rotated symbols | `rotation`, `size` |

## Adding a layer (backend side, no front-end code)
1. Write a script that outputs a GeoJSON to `web/data/processed/` with the style properties above.
2. Add an entry to the manifest:
   ```json
   { "id": "roads", "name": "Roads", "file": "processed/roads.geojson", "type": "line",
     "active": false, "popup": ["name"], "legend": [{"color": "#555", "text": "Main road"}] }
   ```
3. Check it on the published site, then set `active: true`.

A new `type` is the only case that needs front-end work.

## Shared state
`web/state.js` holds `date`, `range`, `sensors`, `confidences`, `hour`, `layers`. Modules change it with `setState()` and react with `subscribe()` — filters, calendar and timeline all go through it.

## Page areas
Stable ids where later modules mount: `#panel-filters`, `#panel-calendar`, `#panel-layers`, `#panel-alerts`, `#timeline`, `#status`.
